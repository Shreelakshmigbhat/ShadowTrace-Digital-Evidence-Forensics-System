# Testing - authentication, investigations, assets, dashboard (Member B)

## How these tests were run
- **Database:** MySQL 8.0.46, freshly rebuilt (`npm run db:reset` equivalent: all `db/sql/*.sql` files in order, including both seed files).
- **Application:** Next.js dev server; requests were made with `curl` using real login cookies (`investigator@shadowtrace.dev`, `admin@shadowtrace.dev`, `analyst@shadowtrace.dev`, `meera.nair@shadowtrace.dev`, all with the seed password `Password@123`).
- **SQL cases** were run through `db/tests/core_tests.sql` with `mysql --force --table`.
- **MongoDB was not available on the machine used for this run**, so cases that need it are marked **NOT RUN**. They are included so they can be executed and filled in where MongoDB is running (`npm run mongo:setup && npm run mongo:seed` first).

## Notes
- TC03 and TC06 temporarily changed user data; the test users were restored afterwards. Re-run `npm run db:reset` to return to the seed state.
- TC04 uses an in-memory limiter, so restarting the dev server clears the counters.
- TC21-TC23 are the only checks for the Mongo `case_notes` collection. The collection scripts type-check and load, and were verified to fail only on the connection when MongoDB is absent, but their behaviour against a real MongoDB is **not** verified here.
